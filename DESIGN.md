# Design rationale: reject, never silently fix

The key decision in this release is that invalid or ambiguous input is rejected with an actionable message instead of being quietly corrected. Unknown categories raise an error rather than being mapped to "other", dates must be exactly `YYYY-MM-DD` (Python 3.11+ would also accept `20260904`, which is easy to mistype), and amounts must be positive with at most two decimals. The decimal rule came from testing: the save/load round-trip test showed that an amount like `18.555` would be written as `18.56`, so a value would change on disk without the user knowing. Instead of accepting that silent data loss, the amount is rejected at entry and the user decides the correct value. All of these rules live in one place (`validation.py`), so the CLI and the CSV loader enforce exactly the same checks, and when a file has problems every bad row is reported at once and nothing is loaded. This makes the program stricter to use, but it guarantees that whatever is stored is exactly what the user meant.
